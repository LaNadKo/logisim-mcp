## 📖 Что это

AI-агент получает доступ к открытому проекту **классического Logisim 2.7.1**: размещает элементы, соединяет реальные выводы, меняет входные сигналы, читает результаты симуляции и сохраняет `.circ`. Изменения появляются в приложении. Сервер использует штатные модели Logisim через Java-агент внутри JVM.

Это самостоятельный проект сообщества. **Logisim Evolution не поддерживается.** Для работы нужен MCP-клиент, например Codex или другой клиент с поддержкой stdio; AI-модель в архив не входит.

### 🎓 Правила для учебных работ

[Инструкция агентам](AGENT_GUIDE.md) автоматически передаётся при подключении MCP. По умолчанию требуется полная реализация задания по методичке и указанному образцу. Компактные подмены, скрывающие структуру блоки и сокращённые отчёты допускаются только по явному запросу или согласованному выбору человека. Требуемая заданием минимизация разрешена. Формулы, карта Карно, схема и отчёт должны соответствовать друг другу.

## 🚀 Быстрый старт

### 1. Скачайте переносимый архив

В [Releases](https://github.com/LaNadKo/logisim-mcp/releases) выберите `logisim-mcp-1.0.0-universal.zip` и распакуйте целиком в доступную для записи папку. `Source code.zip`, создаваемый GitHub автоматически, **не содержит** встроенные среды выполнения.

Архив содержит Python 3.13.15, Temurin JDK 17.0.20.1+1 и Logisim 2.7.1. При первом запуске проверяется SHA-256 и распаковываются только среды для текущей системы. Установка Python/Java, pip, права администратора и интернет для обычного запуска не нужны. Требуются графическая сессия и системные библиотеки ОС; подробности в [совместимости](docs/COMPATIBILITY.md).

### 2. Запустите Logisim

**Windows 10/11 x64:** двойной щелчок по `launch.cmd` либо:

```powershell
.\launch.cmd doctor
.\launch.cmd start
```

**Linux / macOS:**

```sh
sh launch.sh doctor
sh launch.sh start
```

Сохраняйте схемы в `workspace/`. Можно открыть файл сразу:

```sh
sh launch.sh start workspace/example.circ
```

### 3. Подключите MCP-клиент

Сгенерируйте конфигурацию для текущего расположения папки:

```powershell
.\launch.cmd config
.\launch.cmd config --format codex
```

```sh
sh launch.sh config
sh launch.sh config --format codex
```

Перенесите выведенный JSON или TOML в настройки своего MCP-клиента. Конфигурация запускает `mcp` по stdio. После переноса папки на другой путь сформируйте конфигурацию заново. Первая распаковка может занять время: сначала выполните `doctor`, затем подключайте клиент.

## 🔌 Подключение AI

Обычный сценарий: запустить Logisim через `start`, подключить MCP, попросить агента вызвать `projects`, затем работать с возвращённым `ref`.

Пример задания:

> Создай полную схему полусумматора из И, ИЛИ и НЕ. Не используй XOR. Покажи промежуточные выражения, проверь все четыре входных набора и сохрани схему в workspace.

Для подключения к уже открытому классическому Logisim:

```sh
sh launch.sh attach --pid 12345
```

Без `--pid` подключение разрешается только при обнаружении ровно одного подходящего JVM. Logisim должен работать от того же пользователя. Запуск через `start` предпочтителен: агент загружается сразу при старте и не зависит от разрешения динамического attach чужого JVM.

Справка команд: `launch.cmd --help` или `sh launch.sh --help`.

## ⚙️ Настройки

Скопируйте `config.example.json` в `config.local.json`, только если нужны другие пути. Относительные пути отсчитываются от папки MCP. Переменные окружения имеют приоритет.

| Переменная | Назначение | По умолчанию |
| :--- | :--- | :--- |
| `LOGISIM_MCP_WORKSPACE` | Разрешённая рабочая папка файловых инструментов | `workspace/` |
| `LOGISIM_MCP_STATE_DIR` | Локальное состояние и токен | `.state/` |
| `LOGISIM_MCP_JAVA_HOME` | Альтернативный JDK 17+ | Встроенный JDK текущей платформы |
| `LOGISIM_MCP_LOGISIM` | Совместимый classic Logisim JAR | `vendor/logisim-2.7.1.jar` |
| `LOGISIM_MCP_PID` | Явный PID для attach | Автоопределение одного JVM |

При смене workspace переподключитесь, чтобы граница файловых операций обновилась и в Java-агенте. Абсолютные пути в пользовательской конфигурации нужно обновить при переносе. MCP не меняет настройки вашего клиента автоматически.

## ✅ Проверки и ограничения

Поддерживаемые архивы: Windows x64, Linux x64/ARM64, macOS Intel/Apple Silicon. **Наличие архива не означает проверку на физической машине соответствующей платформы.** Актуальные результаты и границы проверки опубликованы в [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md).

- Классический анализатор ограничен восемью однобитовыми входами и выходами. Шины редактируются обычными инструментами.
- Размещение элементов требует координат сетки и реальных портов. Перемещение не перепрокладывает провода.
- Изменения атрибутов выполняются отдельным пакетом от структурных правок.
- Содержимое RAM – состояние симуляции; для переноса используйте hex-экспорт. ROM сохраняется в проекте.
- UI-меню могут выполняться асинхронно. Доступ к Java-методу не доказывает корректность любого его вызова.
- Linux требует графической сессии; для CI используется Xvfb. Пакет не является контейнером с полной операционной системой.

## 🔐 Безопасность

Сервер предназначен для доверенного локального MCP-клиента. Loopback защищён случайным токеном, но универсальные Java API и native-диалоги дают полномочия текущего пользователя: **это не песочница**. Подробности в [SECURITY.md](SECURITY.md).

Для распространения использованной папки создавайте чистый архив через `scripts/package_release.py`. Он исключает токены, конфигурацию, пользовательские схемы, логи и старые сборки.

## 🧪 Разработка

```sh
git clone https://github.com/LaNadKo/logisim-mcp.git
cd logisim-mcp
python3 scripts/fetch_dependencies.py   # Python 3.11+, первый запуск из исходников
sh launch.sh build
sh launch.sh test
```

В Git хранятся код, текущий агент, Logisim и документация. Большие архивы Python/Java поставляются отдельно в переносимом release. Для автономного универсального релиза используйте `fetch_dependencies.py --all` и `package_release.py`. [Инструкция разработчика](CONTRIBUTING.md).
